# 허들링 앱 — 스토리 워크 (실제 작업 방식)

> `docs/story-service.md`가 "무엇을 위한 일인지"의 기준이라면, 이 문서는 "내가 실제로 어떻게 했는지"를 기록한다. 둘은 서로 다른 층위이며 섞지 않는다.

## 원본: AI 없이 손으로 했던 마지막 경험 (7문장)

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다.
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다.
6. 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다.

## 3단계 구조

```
[레퍼런스 분석] (1,2) → G1 → [화면 설계] (3,4,5) → G2 → [디자인 제작] (6,7, 내부 G3)
```

- **G1**: 분석 결과 중 무엇을 반영할지 확정 → 화면 설계 문서 작성 착수
- **G2**: 내부 관계자 협의 후 컨셉 시안 확정 → 디자인 토큰/컴포넌트 제작 착수
- **G3**: 제작 단계 내부의 최종 가이드 위반 검토 게이트
